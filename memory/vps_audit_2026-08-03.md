## Collision-free GasGuard deployment plan

Recommended topology:

```text
Internet
  -> Nginx :80/:443
      -> gasguard.example.com -> HQ frontend container :3100 (internal/loopback)
      -> api.gasguard.example.com -> gateway container :4100 (internal/loopback)

Gateway container
  -> pulls each RU backend gatewayPull endpoint using per-RU sync keys
  -> own persistent database volume
```

Proposed choices:

- Deployment root: `/home/homeauto/gasguard`
- HQ frontend host binding: `127.0.0.1:3100` to avoid occupied ports 3000 and 3002.
- Gateway binding: `127.0.0.1:4100`.
- Do not deploy the RU-local backend on the VPS unless explicitly requested; the VPS gateway should pull RU backends.
- Use Docker Compose with health checks, restart policies, resource limits, named volumes, and a private network.
- Keep secrets only in a VPS `.env` with restrictive permissions; never commit them.
- Generate a non-default JWT secret and unique sync key per RU.
- Point the HQ frontend's `NEXT_PUBLIC_GRAPHQL_URL` to the public gateway API hostname before building the frontend image.
- Add Nginx routes without replacing existing port-80 behavior.
- Use Certbot or another ACME client after DNS records resolve.
